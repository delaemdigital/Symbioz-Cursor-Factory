# Product Brief

## Goal

Convert an idea into a short, testable source of truth before implementation.

## Process

1. Read existing product, architecture, design, roadmap, and decision documents.
2. Extract what is already known. Do not ask for information already present.
3. Define:
   - product / feature name
   - target user
   - problem
   - desired outcome
   - primary user flow
   - acceptance criteria
   - non-goals
   - constraints
   - data involved
   - external systems
   - risks
   - unresolved decisions
4. Separate facts from assumptions.
5. If a missing decision blocks architecture, ask only the minimum necessary question.
6. Save or update the agreed brief in an appropriate docs/product location when requested.

## Output standard

The brief must be concise enough to review, but specific enough that architecture can proceed without guessing.

Do not:
- invent market facts
- invent pricing
- invent metrics
- claim implementation exists
- expand scope silently
